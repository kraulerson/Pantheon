Pantheon Harness — User Guide

How the harness works, what every option does, and how to run it. Last updated 2026-08-19.

Read this first: the harness is half-built. This guide describes what is actually running today, not what is planned. The chat page works as a chat page but is not connected to any AI model yet, and several Configuration buttons do nothing yet. Everything unfinished is listed in What is not built yet and marked in place, so you never go hunting for a button that does not exist.

1. What the harness is, and the addresses

The Pantheon Harness is one machine running several pieces that work together. Everything you use day to day lives under one web address, which exists only inside your home network — nothing is published to the internet, and an outside computer asking for this name gets no answer at all.

AddressWhat it isWho it is for
https://pantheon.ferrumcorde.com The chat page (LibreChat). Conversations, accounts, history. Under the chat box, Terminals opens the harness and Configuration opens setup — both on this same address. Day-to-day use.
https://pantheon.ferrumcorde.com/harness/ The harness: your registered machines, their live tmux sessions, terminal tabs, a Chat tab, and the Approvals inbox. It is drawn in the chat page's own colours and follows its light/dark setting, so the two feel like one place. Development sessions.
https://pantheon-admin.ferrumcorde.com The same console on its own address (the older door). Everything still works there, and the keycard door that Claude-CLI sessions call (§5) answers on both addresses. Scripts and keycards; a fallback if the chat page is down.

Ruled 2026-08-27: the harness moved under the chat address so development sessions stop living behind a door labelled "admin" (the 2026-08-19 "one front door" item, terminal half). Registering machines and minting keycards stay on the Configuration page.

Both are also reachable as pantheon.lan and admin.pantheon.lan if you have those names set up locally. Everything runs on one virtual machine — VM 1093 (192.168.1.93) on the Proxmox server.

2. Signing in

The admin console has no username — just one passphrase. Enter it at /login and you stay signed in for 12 hours, after which you are asked again. Signing out immediately invalidates that session.

The chat page is separate and does have accounts (email + password). Self-registration is switched off: new accounts are created only during a deliberate signup window.

Changing the console passphrase

Run this on the harness machine; it asks twice, shows nothing on screen, and restarts the service itself, so the passphrase never appears in a log or in your shell history:

sudo bash /opt/pantheon/pantheon-harness/scripts/set-operator-passphrase.sh

3. The chat page

Standard LibreChat. Two things here are ours:

  • Terminals and Configuration — the links under the message box; they open the harness and the setup page on this same address.
  • Help & FAQ — in your profile menu; opens this guide.

Two ways to chat: Basic LLM or a persona

When you start a new chat, the endpoint picker (top-left of the message area) offers two kinds of entry. Pick per conversation; you can have both kinds open at once.

EntryWhat you getStatus
Basic LLM - Alden-1 brain (fast) A plain conversation with the big model on the Alden-1 machine (Qwen 3.5, 122B) with its hidden "thinking" switched off: the answer starts in about half a second. No persona, no memory, no tools. Works now.
Basic LLM - Alden-1 brain (thinking) The same model, allowed to think first. You see its reasoning stream in a collapsible "Thinking" block, then the answer — expect 20–40 seconds on even simple questions. Conversations here are not auto-titled (that would cost another 20 s of thinking). Works now.
Basic LLM - 27B llm-mini (fast) The faster 27B model on the graphics-card box, thinking off: answers start in about a third of a second. Same rules: no persona, no memory, no tools. Works now.
Basic LLM - 27B llm-mini (thinking) The 27B allowed to think, reasoning shown. Not auto-titled. Works now.
Pantheon The identity route — talk to Alden-1 the persona, with its memory, its rules and the write-approval gate. This goes through the harness's Facade. Not built yet (skeleton steps 3–8). Sending a message here shows an error until then — see What is not built yet.

Rule of thumb: fast for everyday questions; thinking for puzzles and careful work; Pantheon when you want to talk to a specific identity that remembers and can act (once it is connected). Nothing you say to a Basic LLM entry is stored by the harness or seen by any identity. (Why two entries per model: these models only understand thinking on or off, and the chat page cannot pass that switch from its settings panel yet — a Reasoning-effort setting on every entry is planned with the chat plane.)

4. The harness page

From the chat page, press Terminals under the chat box (or open https://pantheon.ferrumcorde.com/harness/); signing into the console directly lands you on the same page. Down the left is the sidebar: Chat at the top, then one entry per registered machine. Click a machine's name (or the triangle your browser draws beside it) to fold or unfold it, and Collapse all in the Machines heading to fold every machine at once; a ready machine shows a plain-shell button, its live tmux sessions (click one to attach), Refresh, and a box to create a new tmux session; a machine that is not ready says why and links to Configuration. The ☰ Machines button in the header hides or shows the whole sidebar — hiding it gives the terminal the full width — and the page remembers what you left open. The header holds these things:

ControlWhat it does
+ New Session Opens a popup for choosing an AI system and identity. Choosing Claude CLI opens a terminal tab; choosing a chat identity opens a Chat tab that shows the chat page inside the harness (only when the harness was opened from the chat address — from the admin address it offers a link instead, because a browser will not sign you in inside a page from a different address).
Configuration Opens the Configuration page, where everything is registered and set up.
HelpOpens this guide.

Under "Start a session" you get one entry per registered dev machine:

What you seeWhat it meansWhat to do
Claude CLI → name (a button) The machine is set up and switched on. Clicking opens a terminal tab connected to it, in a fresh shell. Next to it, the machine's running tmux sessions appear as name · session buttons — see tmux sessions on a machine. Click it.
name — not provisioned The machine is registered, but the harness has not installed its key on it yet, so it cannot connect. Go to Configuration and use Provision (see section 6).
name — disabled The machine is switched off in the registry on purpose. Enable it (see the known limitation in section 5).

Sessions open as tabs along the top; close one with its ✕. Each state is spelled out in words, never by colour alone.

Selecting and copying text in a terminal

Drag across the text you want. If a full-screen program is using the mouse itself (tmux, the Claude CLI), a plain drag goes to that program instead — on a Mac hold Option (⌥) while dragging, on Windows/Linux hold Shift, and the harness selects instead. Double-click picks a word; right-click picks the word under the pointer. If you see tmux say "copied N characters to tmux buffer", tmux answered the drag, not the harness — hold Option and drag again, or set up tmux's clipboard (below).

The moment you finish selecting, the text is already on your clipboard. ⌘C (or Ctrl+Shift+C) copies it too. Paste with ⌘V.

Letting tmux copy to your clipboard. tmux keeps its own paste buffer, so what it copies is invisible to your Mac unless you tell it to hand the text over. Add these two lines to ~/.tmux.conf on the dev machine and reload tmux (tmux source-file ~/.tmux.conf):

set -g set-clipboard on
set -as terminal-features ',xterm-256color:clipboard'

The harness understands the resulting hand-over (OSC 52) and puts the text on your real clipboard. Without it, use Option-drag so the harness — not tmux — makes the selection.

Ctrl+C is not copy in a terminal — it interrupts whatever is running, and it still does exactly that here. That is why copying uses ⌘C.

tmux sessions on a machine

Beside each ready machine's Claude CLI → name button, the harness asks that machine which tmux sessions are running right now and shows one button per session, labelled name · session. Clicking one opens a terminal tab already inside that session — the same screen you would see by running tmux attach on the machine itself. That is what lets a long-running Claude session survive closing the tab: close it, come back later from any browser, click the same button, and you are looking at the same session again.

What you seeWhat it meansWhat to do
[~] listing tmux sessions on name… The harness is asking the machine. Wait a moment — up to ten seconds if the machine is slow to answer.
name · session (buttons) These sessions are running on the machine right now. Click one to attach. Several tabs, or another computer, can attach to the same session; they all show the same screen.
[–] no tmux sessions on name tmux is installed, but nothing is running. Use + tmux session (below), or the plain Claude CLI button.
[!] name: name unreachable — … The machine did not answer over SSH: asleep, off the network, or the Host/Port is wrong. Wake or check the machine, then press Refresh tmux list.
[!] name: you are signed out — reload the page to sign in Your console sign-in has expired; the machine was never asked. Reload the page and sign in again.
[!] name: tmux list-sessions failed (exit N) — machine said: "…" tmux ran but reported an error. The quoted part is whatever the machine printed — it is shown for diagnosis only; treat it as the machine's words, not the harness's. Run tmux list-sessions on the machine itself to see the full message.
[!] name: tmux is not installed … The machine has no tmux. The harness looks in the usual Homebrew and system places. Install it on the machine (brew install tmux on a Mac), then Refresh.
session (not attachable: unsupported characters in name) A session exists, but its name uses characters the harness refuses to put into a command. Rename it on the machine (tmux rename-session -t old new) using only letters, digits, _ or -.

+ tmux session: type a name — letters, digits, _ or -, up to 64 characters, not starting with - — and press the button. If a session with that name already exists you are attached to it; otherwise it is created and you are attached to the new one. To leave a session running, simply close the tab (or press Ctrl-b then d); the session keeps going on the machine. The list is a snapshot taken when the page loaded (answers are reused for a few seconds, so pressing Refresh repeatedly does not pester the machine) — press Refresh tmux list after starting or ending sessions elsewhere; after + tmux session it re-reads itself a few seconds later.

Pending approvals

The Approvals link at the top of the harness page opens one list of everything that is waiting for your decision — from every session and every identity at once. Each line shows who asked (the identity), which tool, which target (for example the Gitea server), how long ago, its status and a short reference code. The list deliberately shows no request contents — not the text to be written, not the file, not the diff — so it can never leak anything and can never be tricked into running anything.

What the page can say:

You seeIt means
A table of linesThose requests are waiting. Already-decided ones are not listed; a note underneath says how many were left out.
No pending approvals — nothing is waiting on you. Checked: …Every store named after "Checked:" answered and had nothing waiting. The page reads more than one approval store — this harness's own, and any others set up for it (Alden's gateway keeps its own) — and each line says which store it came from.
[!] <store>: the approval gate did not answer …One store could not be read; the lines from the others are still shown. Press Reload; if it persists, that store (not this page) needs attention.
More approvals are waiting than this page showsThe page asks Peta only for waiting items and reads up to ten pages (200 lines at most); press Reload after some have been decided.
N items already resolved not shown / N items without a reference id not shown Peta also returned things that are not waiting, or that cannot be pointed at. They are counted so nothing is hidden silently, but not listed.
[!] the approval gate (Peta) is not configured on this serverThe harness was started without its Peta connection — see the Settings reference.
[!] Could not read the approval queue …Peta did not answer, or answered slowly or oddly. Nothing is lost; press Reload, and check Peta if it persists.

Deciding is not on this page yet: the approve / reject buttons arrive with the M2 approval surface. Until then the page is a read-only inbox.

5. The Configuration page — every field

Reached from Configuration in the harness header, or directly at /admin/config. It has four sections. Each has a form at the bottom for adding a new entry; every entry is saved immediately when you press the add button.

Two limitations that apply to this whole page.
  1. The Edit and Remove buttons do nothing when clicked. The page ships no JavaScript yet, so every one of those buttons is inert (bug #19). To change or delete an entry today, someone has to use the API directly.
  2. The Enabled tick-box is ignored when adding an AI Backend or a Service Endpoint — those two save as switched off no matter what you tick (bug #18). Dev Machines are not affected; that one was fixed.

Dev Machines (Claude CLI)

Each row shows two states, in words:

  • Provisioning — whether the harness has installed its key on the machine. A machine is only usable once this says provisioned.
  • Status — whether it is enabled.
The SSH key is never shown here, and never asked for. The harness holds one private key in a locked directory on its own machine; it is never displayed, never sent to your browser, and never written into a log. Only its public half is installed on your machines.

Session Keycards

A keycard is a small, read-only pass you can hand to a Claude session running on one of your machines, so it can ask the harness questions — which sessions exist, which approvals are waiting (as references only, never the content), how much has been used — without holding your console password or admin token. A keycard cannot change anything, cannot approve anything, and cannot open the Configuration page: it opens exactly one door, /keycard/v1/…, and nothing else.

FieldWhat to put
PrincipalA label for who holds it, e.g. cli-mac-mini. Letters, digits, . _ -; up to 64 characters.
ScopesTick what the holder may read: sessions:read (session list), approvals:read (pending-approval references), usage:read (usage totals — answers "not built yet" until the usage ledger exists). Nothing is ticked by default; an unticked scope is simply refused.
Valid for (days)How long the pass lasts (default 90, at most 365). After that it stops working on its own.

Press Mint keycard. The next page shows the pass once — a long code starting with pk1_. Copy it straight away; it will not be shown again (reloading that page says "already collected"), because the harness keeps only a fingerprint of it. If you forget to tick a scope, the page comes back with a message naming the problem and nothing is minted. Give it to the session as an environment variable (for example PANTHEON_KEYCARD). The session then sends it as a bearer header, e.g. curl -H "Authorization: Bearer $PANTHEON_KEYCARD" https://pantheon-admin.ferrumcorde.com/keycard/v1/whoami.

What you see in the tableWhat it means
[✓] ActiveThe pass works. Revoke stops it immediately.
[x] RevokedYou revoked it; any use is refused. Mint a new one if needed.
[!] ExpiredIts validity ran out; any use is refused.
[!] InvalidThe stored record is unreadable (this should never happen on its own); the pass is refused. Revoke it and mint a new one.
Refused keycard attempts / Rate-limited (below the table)How many times someone presented a pass the harness did not accept, and when it last happened — the way to notice a leaked or replayed pass.
uses / deniedHow often the pass was accepted, and how often it asked for something outside its scopes. A rising "denied" count on a pass you did not expect to misbehave is worth a look.

If a pass leaks, press Revoke — the very next request with it is refused. To rotate, mint a new one first, hand it over, then revoke the old one.

6. Setting up a dev machine, start to finish

Two steps: register it (tell the harness where it is), then provision it (let the harness install its key). Both happen in the browser — you do not need to run anything on the machine itself.

Before you start

  • The machine must accept SSH connections. On macOS: System Settings → General → Sharing → Remote Login, switched on.
  • You need the login password for that machine's user account.

Step 1 — register it

On the Configuration page, fill in the Dev Machines form (Logical Name, Host, Port, User) and press Add Dev Machine. It appears in the list as not provisioned.

Step 2 — provision it

The row now shows a Provision button with a password box. Type that machine's login password and press it. The harness then:

  1. logs in to the machine once using that password,
  2. adds its public key to the machine's list of authorised keys (running it twice is harmless — the key is not added a second time),
  3. disconnects, and reconnects using only the key,
  4. marks the machine provisioned only if that key-only reconnection worked.
What happens to the password. It is used for that single connection and then gone: never saved, never written to any log, never shown back to you, and never passed to a command on the target machine. After this, the harness connects with its key and never needs the password again.

If it fails, the machine deliberately stays not provisioned rather than being recorded as ready. Common causes:

MessageUsually means
could not authenticate … with the supplied password Wrong password, wrong User, or that machine does not allow password logins.
ssh connection failed Remote Login is off, the machine is asleep or off the network, or the Host/Port is wrong.
key-only login still failed The key went on, but the machine refuses it — usually permissions on the target's .ssh folder.

Step 3 — use it

Back on the harness page the machine appears as Claude CLI → name. Click it to open a terminal tab in a fresh shell; closing that tab ends that shell. Its running tmux sessions appear beside it as name · session buttons, and a tab opened from one of those survives being closed — see tmux sessions on a machine.

7. Operating the harness

Everything runs on VM 1093 (192.168.1.93). Two kinds of things run there: the harness's own service, managed by the system; and the third-party pieces, running as containers.

PieceWhat it isHow it runs
Control-planeAdmin console, harness page, terminals systemctl … pantheon-admin@pantheon
LibreChat + Mongo + MeilisearchThe chat page and its storage/searchcontainers
Peta + PostgresTool gateway and its databasecontainers, reachable only from the machine itself
CaddyServes both web addresses over HTTPScontainer

Everyday commands

# restart the admin console
sudo systemctl restart pantheon-admin@pantheon

# is it running?
systemctl status pantheon-admin@pantheon

# the containers
cd /opt/pantheon/pantheon-harness/deploy
sudo docker compose ps
sudo docker compose restart librechat

# update the harness to the latest committed code
cd /opt/pantheon/pantheon-harness && git pull
cd services/control-plane && npm run build
sudo systemctl restart pantheon-admin@pantheon

10. When something goes wrong

SymptomTry this
A page will not load at all Check the console is running: systemctl status pantheon-admin@pantheon. If the chat page is the one failing, check the containers with sudo docker compose ps.
You are sent to the login page repeatedly The 12-hour session has lapsed — sign in again. If it happens immediately every time, the passphrase setting may be empty.
A machine will not provision See the table in section 6.
A terminal will not open The machine must be both provisioned and enabled. Check both words on its row.
